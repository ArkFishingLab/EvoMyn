# 桌面设备同步验收 · 0.2.11

ESP 确认完成的日程通过已有 HTTPS 配对进入桌面应用的 `journal`，与桌面和 MCP 使用同一数据库。应用设置和托盘提供独立开关。关闭 MCP 不停止设备同步；退出应用停止监听，重开后恢复。启动时网络尚未就绪或子进程意外退出，按至少 30 秒间隔重试。

设备原有 NVS 队列在未收到有效持久化回执前保留事件。重复请求核对原始内容并返回相同记录，不重复写入；电脑离线期间的补传仍由设备发起。本次没有修改或烧录固件。

默认分类调整为个人、人脉、日志、资料。未定制的旧目录迁移一次；已有内容的「事件」保留为普通分类，定制名称及顺序不覆盖，不改写记录与历史。

## 隔离验证

- PC Python：194 项，1 项跳过；viewer Python：15 项通过。
- 桌面 Python：36 项，1 项因 Windows 符号链接权限跳过。
- 桌面、viewer、计划兼容与圆屏预览 JavaScript：89 项通过。
- 仓库工具：68 项，3 项平台/权限跳过。
- 固件主机工具：125 项，2 项因 UBSan 环境跳过。Windows 运行需 UTF-8 环境和 Git Bash；不是完整 ESP-IDF 构建或实机验证。
- 真实 TLS 临时库验证：无鉴权拒绝、MCP 关闭仍接收、停启与桌面重启后重放只产生一条日志、桌面与 MCP 均可读取、端口占用故障隔离及退避恢复。
- Windows 打包应用隔离验收：原生配对导入、独立开关、TLS 接收和去重、最近接收时间显示、托盘及退出清理均通过。
- 配对导入和迁移经独立需求、质量检查；发布候选文件通过私有凭证审计。

测试全部使用临时数据库和合成设备身份，没有向安装中的个人记忆库写入测试事项。实机结果与发布后检查另行记录，不能由上述主机验证推定。

## 接入边界

已有设备在「应用设置 → 设备同步」选择包含 `app/.env` 的原配对服务目录，再开启开关。凭证验证后复制到桌面私有目录，来源数据库和固件目录不导入。新设备仍需先完成硬件配对，PC 地址需稳定且网络可达。设置页「接收中」仅说明监听正常，「最近收到」代表持久保存后的成功回执。

设备最多保留 16 条待上传完成事件，满时拒绝新完成操作以免丢失。关闭铃声、取消或稍后提醒不生成完成日志；一般语音记忆不使用该队列。桌面同步入口不承担设备 OTA 发布。
