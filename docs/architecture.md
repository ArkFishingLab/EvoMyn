# 架构与数据边界

`server/personal-memory/` 是 PC 应用源码，`xiaozhi-firmware/` 是设备源码。根目录启动脚本从维护的文件组装 `artifacts/local-memory-mcp/`，或复用已有安装；运行状态不反向成为源码。

## PC 数据流

Codex、Claude Code 等客户端通过 stdio 启动 MCP，与看板共享同一份档案库。看板默认入口为回环地址 `http://127.0.0.1:18768/memory/`，接入配置位于 `/setup/`，能力管理位于 `/memory/mcp/`。

Mnemosyne 保存原始档案、历史版本、双向关联和语义索引。原文持久化与模型索引分离；模型不可用时可保留待索引记录，稍后重试。首次语义检索可能下载本地模型，模型不进入公开源码。

记忆分类存放在同一库的 `personal_archive_categories` 表，初次初始化提供人脉、日志、个人、事件、资料。分类使用稳定编号，改名和排序不改写记录或历史。MCP 通过 `archive_status.categories` 发现当前分类。看板记录 API 仍只读；`/memory/api/categories` 的设置写入要求同源 Origin 和 CSRF 令牌，不加载记忆模型。只读挂载不展示分类编辑入口。

小智云桥接是可选的出站 WebSocket 连接，转接本地 stdio MCP。能力管理决定工具发现及允许调用的工具；商城仅提供已适配目录。世界时间安装在独立环境中，不改变主服务的 MCP 依赖。

## 桌面更新

Windows 桌面默认通过 GitHub Releases 的固定 `latest.json` 地址读取发布说明，随后下载版本专属 EXE。说明由现有 Ed25519 密钥签名；签名、平台、版本、大小和 SHA-256 校验通过后才允许重启安装。源码、签名说明及安装包公开，签名私钥与个人数据始终保留在本机。用户自定义的有效 HTTPS 更新源可覆盖默认地址；旧空配置会使用内置源。检查和下载由用户操作触发，不因启动应用自动更新。

## 可选设备数据流

默认 `PLANNER_OWNER=device`：圆盘保存提醒、离线计时、响铃与完成事件，PC 不启动实时提醒调度或旧计划同步服务。只有用户实际确认完成才产生归档事件；停止铃声不等于完成。

设备在本地持久保存待归档事件，通过所有者配置的 LAN HTTPS 网关上传。PC 写入 journal 并返回稳定回执，设备确认后出队；相同事件重试去重。网关默认关闭，设备证书信任、token、身份和地址均由使用者配置。

定制 OTA 共用独立设备网关的固定下载路由，发布器校验镜像和 manifest。默认没有 OTA 内容。上游小智激活及语音接入与这个可选服务分开。

## 文件边界

| 范围 | 内容 | 公开源码 |
| --- | --- | --- |
| 维护源码 | 服务、页面、工具、测试、文档、上游许可 | 是 |
| 运行副本 | `.env`、`state/`、模型、日志、包环境 | 否 |
| 设备私有配置 | 证书私钥、设备 token、私有 header、NVS/Flash | 否 |
| 构建和历史归档 | 镜像、下载组件、旧 demo、渲染图、原始本机记录 | 否 |

`artifacts/` 与 `backups/` 保留本机内容但被 Git 排除。公开发行使用文件白名单及候选文件审计，不把当前运行目录打包。
